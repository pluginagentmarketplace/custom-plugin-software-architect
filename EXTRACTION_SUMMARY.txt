DEPLOYMENT STRATEGIES
================================================================================

STRATEGY 1: BLUE-GREEN DEPLOYMENT
Description: Two identical production environments
Best For: Zero-downtime critical systems
Rollback Speed: Instant
Complexity: Medium
Timeline: 10-15 minutes per deployment
Tools: AWS Auto Scaling, Kubernetes, Load Balancers
Process:
1. Blue (current) → handles production traffic
2. Green (new) → staged with new version
3. Deploy to Green and run tests
4. Switch router to Green
5. Blue becomes backup
6. If issues: instantly switch back to Blue

STRATEGY 2: CANARY DEPLOYMENT
Description: Gradual rollout to user segments
Best For: Risk mitigation, A/B testing
Rollback Speed: Quick (within minutes)
Complexity: High
Timeline: Hours to days depending on testing
Tools: Istio, Flagger, AWS CodeDeploy, Jenkins
Process:
1. Deploy new version to 5-10% traffic
2. Monitor error rates, latency
3. Increase to 25% → 50% → 75% → 100%
4. Monitor at each phase
5. Instant rollback if issues detected
6. Full production after validation

STRATEGY 3: ROLLING DEPLOYMENT
Description: Sequential instance updates
Best For: Resource-constrained environments
Rollback Speed: Moderate
Complexity: Low
Timeline: 15-30 minutes for typical system
Tools: Kubernetes (default), ECS, Ansible
Process:
1. Add instance with new version
2. Route traffic to new instance
3. Remove old instance from load balancer
4. Shut down old instance
5. Repeat until all instances updated
6. Zero-downtime with gradual transition

API DESIGN PATTERNS
================================================================================

REST API PRINCIPLES
- Resource-oriented design
- HTTP methods: GET, POST, PUT, DELETE, PATCH
- Standard status codes: 2xx (success), 4xx (client error), 5xx (server error)
- JSON/XML payloads
- Stateless communication
- Versioning: /v1/, /v2/, Accept header
- Pagination: cursor-based, offset-based, keyset

GRAPHQL PATTERNS
- Query language for precise data fetching
- Strongly-typed schema definition
- Mutations for data modification
- Subscriptions for real-time updates
- Field-level authorization
- DataLoader for batch optimization
- Error handling with partial responses

gRPC PATTERNS
- Protocol Buffers for serialization
- HTTP/2 for streaming
- Bi-directional communication
- High-performance RPC
- Strong typing
- Language-agnostic

API SECURITY PATTERNS
- Authentication: JWT, OAuth 2.0, API Keys
- Authorization: Role-based, Attribute-based
- Rate limiting: Token bucket, sliding window
- Input validation: Schema validation, sanitization
- CORS: Controlled cross-origin access
- API Gateway: Centralized security

ARCHITECTURE PATTERNS
================================================================================

MONOLITHIC ARCHITECTURE
Structure: Single codebase, single deployment unit
When to Use: Small to medium projects (< 5 developers)
Technologies: Single-language frameworks
Database: Shared single database
Deployment: Single unit deployment
Scaling: Vertical scaling (larger servers)

MICROSERVICES ARCHITECTURE
Structure: Multiple services, independent deployment
When to Use: Large systems (> 10 developers), multiple teams
Technologies: Polyglot, different stacks per service
Database: Database per service, polyglot persistence
Deployment: Independent service deployment
Scaling: Horizontal scaling of individual services
Components:
- Service Discovery (Consul, Eureka)
- API Gateway (Kong, AWS API Gateway)
- Message Queue (Kafka, RabbitMQ)
- Service Mesh (Istio, Linkerd)

SERVERLESS ARCHITECTURE
Structure: Event-driven cloud functions
When to Use: Variable load, event-driven workflows
Platforms: AWS Lambda, Google Cloud Functions, Azure Functions
Benefits: Auto-scaling, pay-per-execution, zero maintenance
Limitations: Cold starts, execution time limits
Use Cases: Image processing, webhooks, periodic tasks

EVENT-DRIVEN ARCHITECTURE
Structure: Services communicate via event broker
When to Use: Decoupled systems, real-time processing
Technologies: Message Brokers (RabbitMQ, Kafka), Event Store
Benefits: Loose coupling, scalability, audit trail (with Event Sourcing)
Patterns: CQRS, Event Sourcing, Saga pattern
